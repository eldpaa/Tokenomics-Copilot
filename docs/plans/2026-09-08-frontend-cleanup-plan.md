## Goal Capsule

- **Objective:** The frontend repository is clean of unused boilerplate templates and standalone sub-projects, ensuring only the core Vite application remains.
- **Means:** Remove the `frontend1/donttouch` and `frontend1/next-app` directories.
- **Stop Condition:** The specified template directories are removed and the main frontend works without issues.

## Product Contract

### Summary
The frontend directory contains old scaffolding (`frontend1/donttouch` and `frontend1/next-app`) that was either generated by mistake or used as reference during early development. These must be removed to avoid confusion and clean up the repository.

### Problem Frame
Leaving multiple standalone frontend projects (Next.js and another Vite app) inside the `frontend1` directory bloats the codebase, causes search pollution, and might confuse new developers or agents about which UI codebase is canonical.

### Requirements

- R1. The standalone `donttouch` project directory must be removed.
- R2. The standalone `next-app` project directory must be removed.

## Planning Contract

- KTD1. **Filesystem cleanup.** The directories will be removed from the file system. Since UI/UX designer tools may be limited in deleting folders, a Node/Bun cleanup script will be generated and executed to remove these directories recursively.

## Implementation Units

### U1. Remove unused frontend directories
- **Goal:** Delete the leftover templates.
- **Files:**
  - `frontend1/donttouch`
  - `frontend1/next-app`
- **Approach:** Use a Node script or file tool to recursively remove the `donttouch` and `next-app` directories from `frontend1/`.
- **Verification:** Run `ls frontend1` and verify the directories are gone.
- **Covers:** R1, R2

## Verification Contract

| Verification Target | Command | Done Signal |
|---|---|---|
| Directory cleanup | `ls frontend1` | `donttouch` and `next-app` are absent |

## Definition of Done

- `frontend1/donttouch` is removed completely.
- `frontend1/next-app` is removed completely.
- The main frontend application in `frontend1` is preserved and unaffected.
